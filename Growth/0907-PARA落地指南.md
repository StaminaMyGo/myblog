# PARA 落地指南

PARA 是 Projects（项目）、Areas（领域）、Resources（资源）、Archives（归档）四类的首字母缩写，由 Tiago Forte 在《Building a Second Brain》（《打造第二大脑》）中提出。其精髓是**按行动状态分类，而非按学科分类**。本文围绕 PARA 四大类的深层判定标准、容易踩的坑，以及如何在 Obsidian 中流畅运转的具体策略展开。

::: tip 适用范围
本文面向已经了解 PARA 基本概念、正在 Obsidian 中搭建或调整个人知识库的使用者；若尚未接触 PARA，可先对照第一节的判定表建立分类直觉。
:::

## 一、重新理解四大类：重点在"本质区别"

很多新手容易在这几类之间纠结，可以使用"灵魂拷问法"做绝对区分：

| 分类 | **核心判定标准（灵魂拷问）** | **生命周期** | **典型例子** |
| :--- | :--- | :--- | :--- |
| **Projects（项目）** | **"这件事有明确的'交付物'和'终点线'吗？"** | 短期、有期限，结束即移走 | 写完毕业论文、制作年终PPT、完成一次旅行规划 |
| **Areas（领域）** | **"这件事我需要长期负责，但没有'做完'的那一天吗？"** | 长期、持续性，永无止境 | 保持身体健康（健身）、提升英语听力、维护家庭财务 |
| **Resources（资源）** | **"这份资料只是'参考'，我不需要为它负责行动吗？"** | 长期积累，被动调用 | 人工智能发展史的资料、喜欢的名言摘录、菜谱大全 |
| **Inbox（收集箱）** | **"我还没想好怎么处理它，需要稍后判断吗？"** | 极短期，中转站 | 突然想到的购物清单、网页剪藏、临时拍的照片 |

## 二、最容易混淆的两组对比（关键）

### Projects vs. Areas（项目 vs 领域）

- **错误做法**：把"保持健康"放进 Projects，然后永远完不成。
- **正确逻辑**：**Areas 是"土壤"，Projects 是"播种"**。例如：Area 是"健身"，Project 是"30 天减脂挑战计划"；挑战结束，成果总结归入 Area 继续维持。
- **操作建议**：在 Obsidian 里，每个 Area 文件夹下可以放一个"项目看板"笔记，动态记录当前关联的 Project 文件。

### Resources vs. Areas（资源 vs 领域）

- **错误做法**：把"编程书籍摘录"放进 Areas，感觉自己在学习，但实际上没有行动。
- **正确逻辑**：如果只是"看着"，放 Resources；如果要"执行"（比如每天刷力扣），放 Areas。
- **一句话判定**：Resources 是**输入**（别人写的），Areas 是**输出**（你执行的）。

## 三、在 Obsidian 里的高级落地玩法

PARA 在 Obsidian 中的落地通常依赖两类机制：文件夹前缀数字排序，以及双向链接。在此基础上，还有三个实操性较强的策略。

### 1. 建立"项目归档"仪式（让 Projects 不腐烂）

当项目结束时，**不要**直接把文件拖进 Archives，而是做三件事：

1. 在项目笔记顶部添加 `状态：已完成 / 已搁置`。
2. 写一条**复盘总结**（收获、教训），并利用 `[[ ]]` 链接回对应的 Area。
3. 再把整个项目文件夹拖入 `04-Archives`。这保证了 Area 里留下的是"经验精华"，而不是"过程废料"。

### 2. 用"MOC（内容地图）"代替深层嵌套文件夹

- PARA 建议文件夹最多两层（`01-Projects/2026-考研复习`）。
- 遇到庞大主题时，**不要在文件夹里建子文件夹**，而是创建一个**MOC 笔记**（如 `英语学习.MOC.md`），在里面用列表和 `[[ ]]` 链接所有相关资源、领域笔记。
- 这样，**物理文件用 PARA 存放，逻辑连接用 MOC 构建**，可以解决"一个文件不知道放哪个文件夹"的问题。

### 3. Inbox 清空"三问法"（避免 Inbox 变成垃圾堆）

建议每天或每周固定时间清空 Inbox，打开每一条笔记，依次问：

- 它是**行动项**吗？→ 丢进对应的 Projects 或转为待办。
- 它是**长期责任**吗？→ 移入 Areas。
- 它只是**参考**吗？→ 移入 Resources，打上标签。
- 如果都不是？→ **果断删除或归档**。保持 Inbox 在 10 条以内，否则它会失效。

## 四、每日/每周维护节奏 SOP

为了让这套系统转起来，建议固化一个简单的维护节奏：

| 频率 | 动作 |
| :--- | :--- |
| **每日（5分钟）** | 打开 `00-Inbox`，看一眼，把其中紧急的行动项拖入 Projects 或生成待办；非紧急的扫一眼即可。 |
| **每周（30分钟）** | 1. **彻底清空 Inbox**；<br>2. 检查 Projects 是否有进展，更新状态；<br>3. 审视 Areas，是否需要新建 Project 来推进某个领域。 |
| **每月（10分钟）** | 打开**图谱视图（Graph View）**，看 Areas 和 Projects 之间有没有缺失的连接（即有没有把项目经验回馈到领域知识中）。 |

## 五、可复用的"文件夹预设"结构

可以直接在 Obsidian 里新建这 5 个文件夹（推荐前缀数字）：

```text
00-Inbox
01-Projects
02-Areas
03-Resources
04-Archives
```

并在 `02-Areas` 里放一个 `_Areas_Index.md`，在 `03-Resources` 里放一个 `_Resources_Index.md`，用列表维护所有核心主题，方便全局检索。

## 六、使用边界与常见误区

- PARA 的判定对象是"行动责任"，不是"内容主题"；同一份资料在不同阶段可以改变归属（例如参考笔记在启动项目后转入 Projects）。
- PARA 适合以行动为导向的个人知识库；对纯收藏型资料库，按主题直接分类可能更简单。
- 系统是否跑偏的一个信号：如果大部分时间都在 `03-Resources` 里翻找资料，说明资源层吸收了过多本应进入 Projects 或 Areas 的内容。

**最后一句建议**：PARA 不是"分类学"而是"行动学"。**它的核心价值不在于把东西放对位置，而在于让你每次打开 Obsidian 时，视线能立刻聚焦在 `01-Projects`（正在做的事）和 `02-Areas`（长期责任）上，从而减少决策消耗。** 如果 90% 的时间你都在 `03-Resources` 里翻找，说明你的系统已经跑偏——资源是为项目和领域服务的，不是让你当收藏家的。
