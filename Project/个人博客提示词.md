# 个人博客排版与扩展规范

::: tip 本文定位
本文是“个人博客提示词”的规范化版本：既可作为博客写作规范，也可作为交给排版助手的任务提示词。
:::

## 一、总体目标

- 将提供的 Markdown 文件扩展为符合 VitePress 渲染要求的文章。
- 保留原文含义，同时让表述更贴切、合理、客观。
- 通过排版降低阅读启动成本，提升可读性。
- 根据内容类型放入对应栏目，避免文章归类和展示混乱。

## 二、VitePress 格式要求

文章需要满足 VitePress 的基本格式要求，具体可参考博客中已发布文章。

### 2.1 使用 frontmatter

每篇文章在开头声明元数据，便于文章列表、搜索和侧边栏读取：

```yaml
---
title: 文章标题
description: 一句话摘要，显示在文章列表中
date: 2026-08-19
tags:
  - 标签一
  - 标签二
---
```

### 2.2 标题层级

- 页面只保留一个一级标题 `#`，通常与 `title` 一致或更具体。
- 二级标题 `##` 用于划分章节。
- 三级标题 `###` 用于章节内的小节。
- 避免跳级使用标题，保持目录结构清晰。

### 2.3 使用 VitePress 增强语法

VitePress 支持普通 Markdown，也支持自定义容器、表格、代码块等高可读性写法：

```markdown
::: tip 提示
适合放补充说明或阅读提示。
:::

::: warning 注意
适合放需要警惕的内容。
:::
```

表格适合做对比，列表适合做并列信息，代码块适合放命令或配置示例。

## 三、文件处理方式

1. 原始文件保持在原路径不变，不在原文件上直接覆盖。
2. 在目标文件夹中新建副本，副本作为排版扩展后的正式文章。
3. 目标文件夹根据内容分类确定，而非统一放在同一目录。
4. 如果原文已经存在于目标文件夹，应使用新文件名或与现有文件明确区分，避免误覆盖。

## 四、文本改写要求

### 4.1 表述更贴切、合理

- 对口语化、碎片化的原文进行整理，使其成为通顺、完整的表达。
- 对概念不清或容易产生歧义的句子，在不改变原意的前提下补充限定条件。
- 用更准确的词语替换模糊表达，但不要堆砌术语。

### 4.2 保持客观叙述

- 尽量用事实和逻辑推进内容，减少情绪化渲染。
- 个人感受可以保留，但应说明这是个人判断，而不是普遍结论。
- 对原文中的夸张、主观断言进行合理收敛。

### 4.3 含义保持原意

- 可以适当扩写，但不能偏离原文观点。
- 可以补充背景、解释和示例，但不能替换成全新的论点。
- 原文中的关键结论、数字、人物和时间应保留。

### 4.4 避免过度修辞

- 不加入过多的比喻。
- 不刻意使用排比句制造气势。
- 优先使用平实、直接的语言表达。

## 五、排版与可读性

排版的目标是让读者在打开文章后快速理解结构和重点，降低阅读成本。

| 排版手段 | 使用建议 |
| --- | --- |
| 章节标题 | 让长文有明确导航，读者可跳读 |
| 有序列表 | 适合步骤、原因、先后关系 |
| 无序列表 | 适合并列要素、特征集合 |
| 表格 | 适合对比、汇总、参数罗列 |
| 引用块 | 适合摘要、原文引用、注意事项 |
| VitePress 容器 | 适合提示、警告、补充说明 |
| 粗体 | 用于突出关键词，不宜大面积使用 |
| 留白与分隔线 | 让内容区块之间边界清晰 |

## 六、内容分类

根据内容类型，将文章放入对应目录：

| 分类 | 目标目录 | 适用内容 |
| --- | --- | --- |
| 技术分析 | `Tech/` | 编程、框架、DevOps、技术原理、工具实践 |
| 产品分析 | `Product/` | 产品拆解、用户体验、商业逻辑、功能分析 |
| ACGN 评价 | `ACGN/` | 动画、漫画、游戏、轻小说及相关文化评论 |
| 项目复盘 | `Project/` | 项目复盘、生活记录、个人感悟、流程规范；无法归入以上三类的统一归入此类 |

分类优先级依次为：技术分析、产品分析、ACGN 评价，最后才是项目复盘。

## 七、执行清单

- [ ] 确认目标文件夹与内容分类。
- [ ] 为文章补充 frontmatter：标题、摘要、日期、标签。
- [ ] 按章节组织原文内容，保留核心含义。
- [ ] 检查是否有多余比喻、排比，删除过度修辞。
- [ ] 使用表格、列表、容器等排版手段提升可读性。
- [ ] 核对原文件未被修改，副本已写入目标文件夹。

> 完成以上步骤后，文章即可进入 VitePress 构建和发布流程。
