# 部分下载 GitHub 文件：按需使用开源项目的四种方法

在实际开发中，经常会遇到这样的需求：一个开源项目整体功能丰富，但当前只需要其中的一部分能力。以 `mattpocock/skills` 技能库为例，该仓库聚合了数十个面向 AI 编程 Agent 的 Skill（技能）文件，而大多数场景下只需使用其中的几个。直接在仓库中复制全部内容既浪费磁盘空间，也会引入无关文件的干扰。

该仓库在设计之初即考虑了模块化与可选择性，因此可以通过以下四种方式按需提取所需文件。下文将逐一说明每种方式的原理、操作步骤与适用场景。

## 一、方法一：使用官方安装器选择安装（推荐）

这是项目文档推荐的标准方式，由安装器自动处理依赖关系，操作最简洁。

```bash
npx skills@latest add mattpocock/skills
```

执行后，安装器会以交互式列表的形式展示仓库内所有可用的技能，支持逐个勾选：

```
? Which skills would you like to add? (Press <space> to select, <a> to toggle all)
  [ ] ask-matt
  [ ] grill-with-docs
  [ ] triage
  [x] improve-codebase-architecture  ← 按空格选中
  [x] setup-matt-pocock-skills        ← 必须选（配置依赖）
  [ ] to-spec
  [ ] to-tickets
  [ ] implement
  [ ] wayfinder
  [ ] prototype
  [ ] diagnosing-bugs
  [ ] research
  [x] tdd                             ← 只选你需要的
  [ ] domain-modeling
  [ ] codebase-design
  [ ] code-review
  [ ] resolving-merge-conflicts
  [ ] wizard
  [ ] grill-me
  [ ] handoff
  [ ] teach
  [ ] to-questionnaire
  [ ] wait-what
  [ ] grilling
  [ ] writing-for-agents
```

使用该方式时需要注意以下关键点：

- 仅 `setup-matt-pocock-skills` 是强制依赖，它负责生成全局配置元数据；
- 其余技能相互独立，可以根据实际需要只选择 1 至 2 个；
- 安装器只拷贝被选中的技能文件到当前项目，不会下载整个仓库内容。

:::: tip 说明
安装器仅将选中的技能文件写入项目本地，生成内容通常只有 `.skills/` 目录与一份很小的配置元数据，不会引入任何未选中的文件。
::::

## 二、方法二：手动从 GitHub 复制特定文件

如果不希望使用任何安装工具，可以直接从仓库页面手动下载指定文件。以 [mattpocock/skills](https://github.com/mattpocock/skills) 为例，操作步骤如下：

1. **定位技能目录**。仓库内的技能按类别组织在子目录中：
   - 工程类技能：`skills/engineering/`
   - 生产力类技能：`skills/productivity/`

2. **复制目标 `SKILL.md` 文件**。每个技能的核心定义都存放在对应目录的 `SKILL.md` 中。例如只需要 TDD 技能时，其文件路径为：
   ```
   https://github.com/mattpocock/skills/blob/main/skills/engineering/tdd/SKILL.md
   ```

3. **按代理要求放置文件**。不同 Agent 工具的技能加载机制不同：
   - **Claude Code**：将 `SKILL.md` 内容复制到 `~/.claude/skills/` 或项目内的 `.claude/skills/` 目录；
   - **Codex**：按其技能配置方式引用该文件；
   - **其他代理**：参考对应代理的技能加载机制进行配置。

4. **同步依赖的辅助文件（可选）**。部分技能会引用同目录下的模板或示例文件，需要一并复制：
   ```
   skills/engineering/tdd/
   ├── SKILL.md
   ├── templates/       ← 如有，需要同步
   └── examples/        ← 如有，需要同步
   ```

:::: warning 注意
手动复制方式完全由使用者控制文件内容，但需要自行处理配置路径与依赖文件的完整性。遗漏辅助文件可能导致技能加载后功能不完整。
::::

## 三、方法三：Fork 并裁剪（适合长期维护）

对于需要长期维护特定技能子集、并持续同步上游更新的场景，可以采用 Fork 后裁剪的方式：

1. **Fork 原仓库**到自己的 GitHub 账号。
2. **删除不需要的技能目录**：
   ```bash
   git clone git@github.com:你的用户名/skills.git
   cd skills
   rm -rf skills/engineering/ask-matt      # 删除不需要的
   rm -rf skills/engineering/wizard        # 删除不需要的
   # ... 只保留你需要的目录
   git push
   ```
3. **使用裁剪后的版本**：
   ```bash
   npx skills@latest add 你的用户名/skills
   ```
   此时安装器只会列出裁剪后保留的技能。
4. **后续更新**：从上游同步变更时，只合并需要的技能目录，其余目录保持不变。

该方式适合团队内部统一技能集、统一版本管理的场景，但要求维护者具备基本的 Git 操作能力。

## 四、方法四：仅使用技能核心逻辑（不依赖文件）

如果只是临时需要某个技能的流程逻辑，也可以不引入任何文件，直接将 `SKILL.md` 中的步骤转化为会话中的口头指令：

1. 打开对应的 `SKILL.md` 文件（如 [`tdd/SKILL.md`](https://github.com/mattpocock/skills/blob/main/skills/engineering/tdd/SKILL.md)）；
2. 阅读其中的执行流程，通常为分步骤的指令序列；
3. 在会话中直接告知代理，例如：
   ```
   请按照 TDD 流程开发：先写一个失败的测试，确保测试能验证当前 bug/功能，
   然后实现代码让测试通过，最后重构。每一步都先向我确认。
   ```

这一方式的本质是将技能逻辑"内化"为口头指令，不产生任何文件依赖。其局限性在于无法复用，每次使用都需要重新描述。

## 五、四种方式对比

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 官方安装器选择 | 自动处理依赖、干净、可更新 | 需要联网 | 首选方式 |
| 手动复制文件 | 完全可控、零依赖 | 需自行处理配置路径 | 只想试水 1 至 2 个技能 |
| Fork 裁剪 | 长期维护方便 | 需要 Git 操作 | 团队内部标准化 |
| 口头指令 | 无需文件、立即生效 | 无法复用、每次需重述 | 一次性使用 |

## 六、最小化示例：只选择 3 个技能

以只使用 **TDD + 代码审查 + 架构扫描** 为例，完整流程如下：

```bash
# 1. 安装器只选这 3 个
npx skills@latest add mattpocock/skills
# 勾选: tdd, code-review, improve-codebase-architecture

# 2. 运行配置
/setup-matt-pocock-skills

# 3. 现在可以调用这些技能了
/improve-codebase-architecture   # 扫描架构
/implement                       # 自动调用 tdd + code-review
```

执行完成后，项目内只会生成 `.skills/` 目录（包含选中的技能文件）与配置元数据，不会引入任何未选中的文件。
