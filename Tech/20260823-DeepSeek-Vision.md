# DeepSeek 视觉能力演进：从 OCR 到多模态 VLM 的技术路径

关于 DeepSeek 在内容审核场景中的视觉处理技术，需要首先澄清一个概念：**"微审模式"并非 DeepSeek 官方的产品命名**。在公开的技术文档、官方公告和 API 文档中，均未找到名为"微审模式"的官方功能。

综合现有信息，"微审模式"很可能是指 DeepSeek 在**内容审核与图像理解场景中所采用的视觉技术方案**，其底层技术经历了从**专用 OCR 模型**到**多模态视觉语言模型（VLM）** 的演进历程。下文按时间线梳理这一演进过程，帮助理解各阶段的技术本质。

## 一、技术前夜：纯文本大模型时代的视觉能力缺失（2023 年—2025 年初）

### 1.1 DeepSeek 的纯文本定位

DeepSeek 的主体运营公司杭州深度求索成立于 2023 年。在成立后的相当长一段时间内，DeepSeek 系列模型均为**纯文本大语言模型（text-only LLM）**，不具备任何原生的视觉输入能力。模型在架构层面被声明为只支持 `text` 这一种输入模态。

这意味着，当用户向 DeepSeek 上传一张图片时，模型既无法"看到"图片内容，也无法理解其中的视觉信息——它只能感知到文件附件的存在，却无法读取其中的任何内容。

### 1.2 内容审核的现实需求与技术瓶颈

在纯文本阶段，DeepSeek 的内容审核能力主要依赖以下技术路径：

- **文本层面的关键词过滤与规则匹配**：对用户输入的文本进行敏感词检测和模式匹配；
- **基于大语言模型的语义理解审核**：利用模型自身的语言理解能力，对文本内容的语义风险进行评估；
- **输出后处理与毒性评分**：对模型生成的内容进行安全检测和自动改写。

然而，这种纯文本架构在面临**图像类内容审核**时存在根本性瓶颈：

**第一，无法处理图像输入。** 用户上传的截图、文档扫描件、代码截图、架构图等视觉内容，在纯文本模型面前完全"不可见"。

**第二，传统 OCR 方案的局限性。** 即使在前端引入 OCR（光学字符识别）工具将图片转为文字，传统 OCR 技术也存在明显缺陷：它仅能提取图像中的文字字符，无法理解文档的**版面结构、阅读顺序、语义层级和图文关系**。例如，面对一份包含表格、标题、段落和公式的 PDF 扫描件，传统 OCR 可以识别出所有字符，但无法判断哪些是表头、哪些是正文、公式如何排版。

**第三，敏感信息识别的精准度问题。** 在内容审核场景中，仅靠 OCR 提取文字加关键词匹配，无法识别经过变形处理的敏感信息（如 `password` 写成 `passw0rd`、`admin` 写成 `adm1n`），也无法理解代码中的语法结构和上下文语义。

### 1.3 外部社区的"补眼"方案

由于 DeepSeek 自身缺乏视觉能力，开源社区和开发者开始自发地为 DeepSeek 补齐视觉能力，主要方案包括：

**方案一：视觉模型前置。** 在 DeepSeek 前接入一个独立的视觉语言模型（如 Qwen-VL），先将图片转换成文字描述，再把文字交给 DeepSeek 进行推理。

**方案二：Harness 插件方案。** 修改 DeepSeek Harness（DeepSeek 的 Agent 框架），让图片先保存到工作区，再由视觉插件、脚本或子 Agent 读取并处理。

GitHub 上出现了多个类似的 vision bridge 插件，甚至有开发者专门做出了 `dsh-deepseek-vision`——图片先交给其他视觉语言模型理解，再把描述传给 DeepSeek。

这形成了一个略显尴尬的局面：DeepSeek 已发布高度插件化的 Agent Harness，Agent 能够调用终端、文件、代码和外部工具，但面对最常见的截图、网页图片和报错界面时，仍需要借用其他公司的模型。

## 二、第一代视觉能力：DeepSeek-OCR 系列专用模型

### 2.1 DeepSeek-OCR 的诞生与技术架构

DeepSeek-OCR 是 DeepSeek 推出的**首个专用视觉模型**，参数量为 **3B**，定位为光学字符识别和文档理解模型。

其核心技术创新在于**"上下文光学压缩"（Contextual Optical Compression）**——将二维布局信息转换为视觉标记（visual tokens），而非简单地逐像素或逐字符处理。

技术参数与能力：

- 能处理**表格、论文和手写内容**，识别精度达到 **97%**；
- 使用的视觉标记比纯文本标记**少 10 倍**，推理效率比基于文本的 LLM**高 10 倍**；
- 支持通过 **vLLM** 进行流式调用，在 streaming 模式下生成 Markdown、结构化数据或图文描述，具备**低延迟、高并发**的推理能力；
- 可进行微调以提升视觉或语言性能。

### 2.2 DeepSeek-OCR-2：视觉因果流技术的突破

DeepSeek-OCR-2 是 OCR 系列的重大升级版本，其核心创新是**视觉因果流技术（Visual Causal Flow）**。

**技术原理：**

传统 OCR 将图像视为像素点的集合，按固定顺序（如从左到右、从上到下）扫描提取文字。而 DeepSeek-OCR-2 模拟了**人类阅读文档的认知逻辑**：

1. **全局感知**：DeepEncoder V2 架构先对整张图片进行全局感知，识别出标题区域、代码块、图表、注释等不同内容区域；
2. **语义驱动的动态优先级**：不按固定顺序处理，而是**根据语义关系动态调整处理优先级**。例如，处理 SQL 查询截图时，模型会**优先聚焦于代码块区域**（因为那里最可能包含需要审核的敏感信息）；处理 API 文档截图时，会**特别关注 URL 路径和请求参数部分**；
3. **结构理解优先于字符提取**：先理解文档的整体结构（如"继承关系""依赖箭头"等语义信息），再关注细节内容。

**技术效果：**

在 CSDN 技术社区的实际测试中，DeepSeek-OCR-2 对技术文档的**字符准确率达到 91.1%**，比前代提升了 8.4 个百分点；**阅读顺序的识别准确率**大幅提升，编辑距离从 0.085 降低到 0.057。

更重要的是，它不仅能正确识别出 `SELECT * FROM users WHERE id = 123;` 这样的 SQL 语句，还能**准确理解这是 SQL 语句而非普通文本**，为后续的敏感信息识别打下基础。

### 2.3 DeepSeek-OCR-2 在内容审核中的落地

CSDN 技术社区是 DeepSeek-OCR-2 在内容审核场景中的重要应用案例。

**审核挑战：** CSDN 每天有大量开发者上传技术文档、代码截图、架构图、学习笔记等，形式包括印刷体文字、手写标注草图、模糊的手机拍摄截图、多列排版的 PDF 论文，甚至包含数学公式、流程图和代码块的混合文档。

**传统方案的失败：** 传统 OCR 在处理这类技术内容时常常力不从心。例如，一张 Spring Boot 配置的代码截图，基础 OCR 可能将 `@Configuration` 识别成 `@Confguration`，将 `application.yml` 识别成 `application.yrnl`；一张包含 UML 类图的图片，传统工具只能提取零散的文字，无法理解"继承关系""依赖箭头"等语义信息。

**DeepSeek-OCR-2 的解决方案：** 在 CSDN 的内容审核流程中，DeepSeek-OCR-2 承担着"第一道眼睛"的角色。它不只是简单地把图片转成文字，而是帮助审核系统**理解文字背后的含义和风险等级**。

具体来说，DeepSeek-OCR-2 结合**上下文理解进行智能识别**。当它识别出一段代码时，会同时分析这段代码的**语法结构、变量命名习惯和所在上下文**。例如，在 Python 代码中发现 `os.environ.get('API_KEY')` 这样的模式时，模型会结合上下文判断这是否是真实的敏感信息暴露，还是仅仅是示例代码。

**第一代技术的定位总结：**

DeepSeek-OCR 系列的本质是**专用视觉模型**，其核心能力是**文档理解与 OCR**，而非通用视觉理解。它擅长从图像中提取文字并理解文档结构，但不具备识别物体、人脸、场景等像素级视觉理解能力。

## 三、第二代视觉能力："识图模式"上线（2026 年 4 月—6 月）

### 3.1 上线时间与技术定位

2026 年 4 月 29 日，DeepSeek 在网页端悄然上线了**"识图模式"**，并配以标志性鲸鱼"摘下眼罩"的宣传图，宣告其多模态能力正式落地。

此前，DeepSeek V4 纯文本模型刚于 4 月 24 日发布，短短五天内即推出视觉理解功能。这标志着 DeepSeek **从纯文本大模型正式迈入视觉理解时代**。

2026 年 6 月 18 日，DeepSeek 网页端及 APP 端均正式新增了"识图模式"，显示"图片理解功能内测中"。同一天，DeepSeek 多模态团队负责人在社交媒体上发文称，视觉模式已在网页和应用上正式上线。

### 3.2 "识图模式"的底层技术：OCR 而非 VLM

**关键结论：DeepSeek"识图模式"的底层技术是 OCR 模型，而非多模态视觉语言模型（VLM）。**

DeepSeek 官方在回应中明确表示：目前的"识图功能"其实是"读图"。DeepSeek 目前支持的图像文件上传和视觉识别为**OCR 模型**，即读取图像中的文本，擅长从上传的图像（PDF、Word、Excel、PPT、JPG 等）中读取文本并处理该文本；**而不是多模态视觉语言模型（VLM）**，无法以像素级别"看到"物体、人脸或场景。

这一技术定位在实际测试中得到了验证：

**人脸识别测试失败：** 有测试者上传特定人物照片，DeepSeek 出现误判。DeepSeek 表示**自己没有人脸识别模块，不会"看脸"只会"看字"**，如果照片中只有一张脸，会回复"图片中没有文字内容"。

**文字识别测试：** 对于新闻资讯封面图，DeepSeek 基本可以识别出内容，但部分文字存在错别；对于书法作品，可以识别部分文字，但存在原文误判；对于英文公告截图，可正确识别并翻译。

### 3.3 技术能力与局限

**支持的能力：**

- 从上传的图片（JPG、PNG 等）中**读取文字内容**；
- 理解文字之间的**逻辑关系**（如标题-正文、表格行列）；
- 将图片内容转换为 **Markdown、结构化数据或图文描述**；
- 支持通过 **vLLM** 调用，具备**低延迟、高并发**的推理能力；
- 支持**流式（streaming）模式**生成输出。

**不具备的能力：**

- 无法以像素级别"看到"物体、人脸或场景；
- 不具备人脸识别模块；
- 不具备通用视觉理解能力。

### 3.4 "识图模式"的技术架构

从技术架构角度看，"识图模式"的运作流程可以概括为：

1. **图像输入**：用户上传图片（支持 PDF、Word、Excel、PPT、JPG 等多种格式）；
2. **OCR 提取**：DeepSeek-OCR 模型从图像中提取文字内容；
3. **文本处理**：提取出的文字进入主模型对话流程，由纯文本大模型进行理解、推理和生成；
4. **结果输出**：返回图文结合的分析结果。

这种架构的本质是 **"OCR 前置 + 纯文本 LLM 后处理"** 的流水线模式，而非端到端的多模态理解。

## 四、第三代视觉能力：V4-Flash-Vision-Exp 多模态模型（2026 年 8 月）

### 4.1 上线时间与技术突破

2026 年 8 月 21 日，DeepSeek 官方 API 文档上线了全新的多模态视觉理解模型 **DeepSeek-V4-Flash-Vision-Exp**，这是一个**实验性质的多模态视觉语言模型（VLM）**。

这是**DeepSeek V4 系列首个直接支持图片输入的视觉模型**。用户可以通过设置 `model='deepseek-v4-flash-vision-exp'` 访问该模型。

### 4.2 技术参数

| 技术指标 | 参数 |
|---------|------|
| 上下文长度 | **1M** tokens |
| 最大输出长度 | **384K** tokens |
| 单张图片最大 Token 数 | **384 tokens** |
| 计费方式 | 图片按尺寸折算成 Token，与文本 Token 一同计费 |
| API 支持 | Chat Completions、Messages、Responses 三种格式 |
| 图片传入方式 | base64 内联、外部 URL、Files API 三种方式 |

### 4.3 技术能力

**多模态 Agent 能力：** 官方表示，V4-Flash-Vision-Exp 在纯文本能力方面已与 DeepSeek-V4-Flash 正式版持平；在需要视觉理解的 Agent Benchmark 上，**多模态 Agent 能力已接近 Opus-4.8**。

**评测数据（部分）：**

| Benchmark | V4-Flash-Vision-Exp | Opus-4.8 |
|-----------|---------------------|----------|
| Terminal Bench 2.1 | 83.9 | 85.0 |
| NL2Repo | 57.7 | 69.7 |
| Toolathlon-Verified | 75.9 | 76.2 |
| Chartography | 64.3 | 65.0 |
| ZeroBench (Pass@5) | 35.0 | 34.0 |

### 4.4 从 OCR 到 VLM 的技术演进逻辑

V4-Flash-Vision-Exp 的上线标志着 DeepSeek 视觉技术的质变：

| 维度 | OCR 时代（识图模式） | VLM 时代（V4-Flash-Vision-Exp） |
|------|-------------------|-------------------------------|
| 技术本质 | 文字提取工具 | 视觉理解模型 |
| 输入理解 | 仅能提取文字 | 理解像素级视觉信息 |
| 人脸识别 | 不支持 | 支持 |
| 物体识别 | 不支持 | 支持 |
| 场景理解 | 不支持 | 支持 |
| 技术架构 | OCR + 纯文本 LLM 流水线 | 端到端多模态模型 |

**为什么 DeepSeek 先做 OCR 再做 VLM？**

从技术演进路径来看，DeepSeek 选择了一条**渐进式**的视觉能力建设路径：

1. **先解决"能读"的问题（OCR 阶段）**：通过专用 OCR 模型，让系统至少能从图像中提取文字信息，满足最基本的内容审核需求；
2. **再解决"能看"的问题（VLM 阶段）**：通过端到端的视觉语言模型，实现真正的像素级视觉理解。

这种策略的技术合理性在于：

- OCR 模型的**训练成本和数据需求远低于 VLM**，可以快速上线；
- 内容审核场景中，**文字内容是最核心的审核对象**，OCR 已经能覆盖大部分需求；
- VLM 的训练需要**大规模的图文配对数据**和更复杂的模型架构，开发周期更长。

### 4.5 Harness 框架的配套升级

值得注意的是，DeepSeek 对视觉能力的准备其实已经提前写进了 Harness 框架。

DeepSeek Harness 最新 rc.8 版本的 Release Notes 明确增加了一项功能："增强多模态支持度，DeepSeek 模型适配器支持配置启用原生图片请求"。与此同时，`/goal`、`/plan` 等命令开始支持图文输入，`@` 菜单能够引用文件和会话；官方还修复了图片尺寸过大、历史图片载荷过高导致模型请求失败等问题。

这一配套升级的意义在于：**视觉能力不是孤立的功能，而是 DeepSeek Agent 系统的基础感知入口**。V4-Flash-Vision-Exp 的出现，让此前相对独立的模型、图片、文件、工具和 Agent 执行链开始连在一起。

## 五、技术总结

### 5.1 "微审模式"的底层技术答案

回到最初的问题：**DeepSeek"微审模式"的底层技术是使用 OCR 还是大模型等视觉相关技术？**

答案是：**两者兼有，但分阶段。**

- **在"识图模式"阶段（2026 年 4 月—8 月）**：底层技术是**OCR 模型**（DeepSeek-OCR / DeepSeek-OCR-2），属于专用视觉模型，核心能力是文档文字提取与结构理解；
- **在 V4-Flash-Vision-Exp 阶段（2026 年 8 月 21 日起）**：底层技术是**多模态视觉语言模型（VLM）**，属于大模型视觉相关技术，具备端到端的像素级视觉理解能力。

### 5.2 完整技术演进时间线

| 时间节点 | 事件 | 技术本质 |
|---------|------|---------|
| 2023 年 | DeepSeek 公司成立 | 纯文本 LLM |
| 2024 年 6 月 | DeepSeekChat 算法备案 | 纯文本 LLM + 文本审核 |
| 2025 年初 | DeepSeek 广泛出圈 | 纯文本 LLM |
| 2025 年 4 月 28 日 | 地方政府应用 DeepSeek 打造 AI 智能预审系统 | 纯文本 LLM + 外部 OCR |
| 2025 年 5 月—7 月 | 第三方推出 DeepSeek 内容安全方案 | 端侧小模型 + 云端大模型 |
| 2026 年 2 月 | CSDN 应用 DeepSeek-OCR-2 进行内容审核 | DeepSeek-OCR-2 专用视觉模型 |
| **2026 年 4 月 29 日** | **DeepSeek"识图模式"上线** | **DeepSeek-OCR（专用模型）** |
| 2026 年 6 月 18 日 | "识图模式"全量上线 | DeepSeek-OCR（专用模型） |
| **2026 年 8 月 21 日** | **V4-Flash-Vision-Exp 上线** | **多模态 VLM（大模型视觉）** |

### 5.3 技术演进的核心驱动力

从技术角度分析，DeepSeek 视觉能力演进的驱动力包括：

**1. 内容审核场景的刚性需求。** 技术社区、政务服务平台等内容审核场景中，图像类内容占比越来越高，纯文本模型无法满足需求。

**2. OCR 技术的局限性倒逼升级。** 传统 OCR 只能提取文字无法理解语义，即使 DeepSeek-OCR-2 引入视觉因果流技术实现了结构理解，仍然无法处理人脸、场景等纯视觉理解任务。

**3. Agent 生态的视觉入口需求。** DeepSeek Harness 作为 Agent 框架，需要视觉能力作为感知入口，让 Agent 能够处理截图、网页图片和报错界面等视觉输入。

**4. 多模态大模型的技术趋势。** 多模态已成为大模型产品的标配，DeepSeek 需要在国产大模型竞争中补齐多模态短板。
