# 为什么 GitHub Pages 是“免费”的？

::: tip 阅读提示
GitHub Pages 对个人开发者免费开放，但这并不意味着服务没有成本。本文从边际成本角度解释 GitHub 的 CDN 分发成本为什么足够低，以及这种模式为什么能够支撑免费策略。
:::

## 一、核心概念：什么是边际成本？

在经济学中，边际成本（Marginal Cost）指每多生产或提供一个单位的产品或服务时，所增加的成本。

当讨论 GitHub 的 CDN（内容分发网络）时，“边际成本极低”意味着：GitHub 每多向全球用户分发一份文件（如代码、图片、文档），其额外付出的成本几乎可以忽略不计。这种成本结构是 GitHub 能提供免费 Pages 服务的基础。

## 二、为什么 GitHub 的全球 CDN 边际成本极低？

### 1. 基础设施规模效应

GitHub 依托微软 Azure 的全球基础设施，在全球各地部署了大量边缘节点。当 CDN 网络规模足够大时，固定成本（如服务器采购、机房建设、骨干网带宽租赁）会被庞大的用户基数和请求量摊薄。

用户量越大，单次请求分摊到的固定成本就越低。这是典型的规模效应：基础设施投入已经发生，新增请求只需要利用既有容量。

### 2. 高度自动化的资源调度

GitHub 的 CDN 采用自动化的缓存和路由策略。用户请求资源时，系统会自动从距离最近的边缘节点返回数据，而不需要每次都回源到中心服务器。

这种机制减少了中心服务器的计算压力和带宽压力。多分发一份数据时，额外开销主要体现在边缘节点的小幅带宽消耗上，而边缘节点的容量已经被大规模请求充分利用。

### 3. 开源生态带来的持续流量

GitHub 是全球最大的开源代码托管平台，每天有大量开发者上传、下载和同步代码。这种持续且高频的自然流量，使 GitHub 的 CDN 长期处于高利用率状态。

在高利用率下，新增的静态页面请求只是总流量中的一小部分，不需要单独购置大量物理资源。对 GitHub 来说，Pages 流量与代码仓库流量共享同一套基础设施，边际成本因此被进一步压低。

### 4. 协议优化与压缩技术

GitHub 在 CDN 链路上使用了现代网络协议，例如 HTTP/2、HTTP/3、QUIC，并配合高效的数据压缩算法。这意味着传输相同内容时，实际消耗的带宽更少。

带宽是 CDN 成本的主要组成部分。带宽利用率提升后，单位内容的传输成本下降，边际成本也随之降低。

## 三、GitHub Pages 免费不等于服务无成本

GitHub Pages 的免费是商业策略，而不是没有成本。以下几点需要区分：

| 层面 | 说明 |
| --- | --- |
| 用户侧成本 | 个人开发者无需为静态托管和基础 CDN 分发付费 |
| 企业侧成本 | 服务器、带宽、维护、安全等成本由 GitHub / 微软承担 |
| 商业收益 | 免费服务吸引开发者留在 GitHub 生态，带动付费企业版、Actions、Copilot 等业务 |
| 使用限制 | 免费 Pages 仍有使用政策和服务条款约束，不代表可以无限量滥用 |

因此，更准确的表述是：GitHub 通过规模效应和生态策略，将单个用户的边际成本压到足够低，从而可以承担免费模式。

## 四、总结

GitHub Pages 能够免费，是因为其 CDN 具备以下条件：

- 大规模基础设施摊薄固定成本
- 自动化缓存与就近分发降低回源压力
- 开源生态提供持续高流量，提高资源利用率
- 现代协议与压缩技术降低单位带宽消耗

当基础设施和流量规模达到一定程度后，多服务一份静态页面带来的额外成本很低。这种极低的边际成本，加上免费策略对开发者生态的拉动作用，共同构成了 GitHub Pages 免费模式的底层逻辑。
