# Notion 与魔搭的 MCP 构建之道：为什么 AI 不能直接操纵软件

## 一、问题的提出

随着 AI 助手（如豆包、ChatGPT、Claude）的能力越来越强，一个自然的问题浮现出来：**为什么 AI 不能直接操纵软件？**

比如：

- 为什么 AI 不能直接打开 Notion，帮我创建一个页面、整理我的笔记？
- 为什么 AI 不能直接打开 Photoshop，帮我修图？
- 为什么 AI 不能直接打开 Excel，帮我做数据分析？
- 为什么 AI 不能直接操作任何一个桌面软件？

看起来，AI 已经很聪明了——它能理解自然语言、能写代码、能分析数据、能生成内容。那为什么它不能直接"用"软件呢？

与此同时，我们看到 Notion、魔搭（ModelScope）等平台都在构建自己的 MCP（Model Context Protocol）能力。MCP 是什么？为什么这些平台要构建 MCP？MCP 和"AI 直接操纵软件"有什么关系？

本文将系统性地分析这些问题：

1. 为什么 AI 不能直接操纵软件？（技术、安全、体验三个维度）
2. MCP 是什么？它解决了什么问题？
3. Notion、魔搭等平台是如何构建自己的 MCP 的？
4. 未来的方向是什么？

## 二、为什么 AI 不能直接操纵软件

要回答这个问题，我们需要从三个维度来分析：**技术维度、安全维度、体验维度。**

### 技术维度：软件的"界面"不是为 AI 设计的

**第一个核心问题：软件的用户界面（UI）是为人类设计的，不是为 AI 设计的。**

人类使用软件的方式是：

- 用眼睛看屏幕（获取视觉信息）
- 用大脑理解界面（识别按钮、菜单、文本）
- 用手操作鼠标/键盘/触摸屏（输入指令）

这个过程依赖于人类的视觉理解、空间认知、运动控制等能力。而 AI（特别是大语言模型 LLM）的核心能力是**文本理解和生成**，它没有眼睛、没有手、没有空间认知能力。

如果要让 AI 直接操纵软件，它需要：

1. **"看到"屏幕**：通过截图或屏幕共享获取视觉信息
2. **理解界面**：识别截图中的按钮、菜单、文本、布局
3. **决策操作**：决定下一步该点击哪里、输入什么
4. **执行操作**：模拟鼠标点击、键盘输入

这个流程在技术上是可行的（比如有一些 AI 浏览器自动化工具、RPA 工具），但存在很多问题：

**问题一：视觉理解的不准确性**

LLM 可以通过多模态能力"看"截图，但它的视觉理解能力远不如人类。它可能会：

- 认错按钮（把"取消"看成"确定"）
- 漏看重要信息（忽略了一个弹窗）
- 误解布局（不知道该点哪里）
- 无法处理动态界面（下拉菜单、动画、状态变化）

**问题二：操作的不可靠性**

即使 AI 理解了界面，执行操作也可能出错：

- 点击位置偏移（点到了旁边的按钮）
- 输入内容错误（多打了一个字、格式不对）
- 时序问题（操作太快或太慢，界面还没加载完）
- 异常处理（遇到弹窗、报错、网络延迟，不知道该怎么办）

**问题三：效率低下**

通过"看截图 → 理解 → 决策 → 模拟操作"的方式操纵软件，效率非常低。每一步都需要：

- 截图（几百毫秒到几秒）
- 传给 AI 模型分析（几秒到几十秒）
- 生成操作指令
- 执行操作（几百毫秒）

一个简单的操作（比如"创建一个新页面"），可能需要好几轮交互，耗时几十秒甚至几分钟。而人类只需要几秒钟。

**问题四：无法处理复杂的软件逻辑**

很多软件有复杂的内部逻辑——状态管理、数据校验、权限控制、异步操作等。AI 通过界面操作很难理解和处理这些逻辑。比如：

- 为什么这个按钮是灰色的？（需要理解权限和状态）
- 为什么保存失败了？（需要理解数据校验规则）
- 为什么页面跳转了？（需要理解应用的路由逻辑）

这些问题，通过"看界面"是很难回答的。

### 安全维度：让 AI 直接操纵软件太危险

**第二个核心问题：让 AI 直接操纵软件，存在严重的安全风险。**

想象一下，如果 AI 可以直接操纵你的电脑和软件，它可以：

- 删除你的文件
- 发送你的私人信息
- 转账（如果它能操作银行 App）
- 修改你的系统设置
- 安装恶意软件
- 以你的名义发邮件、发消息

即使 AI 本身是"善意的"，也可能因为：

- 理解错误（把"删除这个文件"理解成"删除所有文件"）
- 操作失误（点错了按钮）
- 被提示注入攻击（恶意网页/文档中的指令诱导 AI 做坏事）
- 模型幻觉（AI"想象"出了一个不存在的操作）

而造成严重的后果。

**更重要的是：AI 直接操纵软件，绕过了所有的安全边界。**

现代操作系统和软件都有完善的安全机制：

- 权限控制（哪些应用可以访问哪些资源）
- 沙箱隔离（应用之间互不干扰）
- 用户确认（危险操作需要用户手动确认）
- 审计日志（所有操作都有记录）

但如果 AI 是通过"模拟人类操作"的方式来操纵软件，它就绕过了所有这些安全机制——因为在系统看来，这些操作就是"用户"做的。AI 可以点击任何按钮、输入任何内容、执行任何操作，而系统无法区分这是人类还是 AI 在操作。

**这就像给了 AI 一把可以打开任何门的万能钥匙——一旦 AI 出错或被攻击，后果不堪设想。**

### 体验维度：直接操纵的体验很差

**第三个核心问题：即使技术和安全问题都解决了，AI 直接操纵软件的用户体验也很差。**

**问题一：用户无法预测和控制 AI 的行为**

如果 AI 直接在你的屏幕上操作，你会看到：

- 鼠标在自己动
- 窗口在自己切换
- 内容在自己变化

这种"幽灵操作"的感觉很不舒服，而且你无法预测 AI 下一步会做什么，也无法在中途方便地干预和停止。

**问题二：出错了很难调试和恢复**

如果 AI 操作出错了（比如删错了文件、填错了表单），你很难：

- 知道它为什么出错（黑盒操作）
- 回滚到之前的状态（没有操作历史）
- 防止同样的错误再次发生（无法精确控制）

**问题三：无法并行和复用**

AI 直接操纵软件，一次只能操作一个界面，无法并行处理多个任务。而且，每次操作都是"一次性"的，无法方便地复用和自动化。

**问题四：对软件的破坏性**

AI 直接操作软件，可能会：

- 改变软件的设置（而且改不回去）
- 留下操作痕迹（浏览历史、缓存等）
- 触发软件的防自动化机制（被判定为机器人，封号等）

## 三、MCP 是什么：AI 与软件之间的"协议层"

理解了"AI 直接操纵软件"的问题，我们就能理解 MCP 为什么重要了。

### MCP 的定义

**MCP（Model Context Protocol，模型上下文协议）**是由 Anthropic 提出的一个开放协议，它的目标是：**为 AI 模型和外部工具/数据源之间提供一个标准化的连接方式。**

简单来说，MCP 就像是 AI 和软件之间的"翻译官"和"安全门卫"：

- AI 不需要直接操纵软件的界面
- 软件不需要专门为每个 AI 模型做定制集成
- MCP 在中间提供一个标准化的接口，让 AI 可以安全、可靠、高效地调用软件的能力

### MCP 的核心概念

MCP 有几个核心概念：

**MCP Server（MCP 服务器）**

每个软件/服务可以运行一个 MCP Server，它暴露了该软件的能力（比如"创建页面"、"读取笔记"、"搜索内容"）。

**MCP Client（MCP 客户端）**

AI 助手（如 Claude、豆包）作为 MCP Client，可以连接到多个 MCP Server，调用它们暴露的能力。

**Tools（工具）**

MCP Server 暴露的具体能力，比如 Notion 的 MCP Server 可能暴露：

- `create_page`：创建页面
- `get_page`：读取页面内容
- `search_pages`：搜索页面
- `update_page`：更新页面内容

**Resources（资源）**

MCP Server 可以提供的数据源，比如 Notion 的页面、数据库、块等。

**Prompts（提示词模板）**

MCP Server 可以提供预定义的提示词模板，帮助 AI 更好地使用该工具。

### MCP 如何解决"AI 直接操纵软件"的问题

理解了 MCP 的概念，我们就能看到它如何解决前面提到的问题：

**解决技术问题：从"界面操作"到"API 调用"**

MCP 让 AI 不需要"看界面、点按钮"，而是直接调用软件暴露的 API（通过 MCP 封装）。这意味着：

- 不需要视觉理解（不会认错按钮）
- 不需要模拟操作（不会点错位置）
- 效率高（一次 API 调用，不需要多轮交互）
- 可靠（API 有明确的输入输出，行为可预测）

**解决安全问题：从"万能钥匙"到"权限可控"**

MCP 提供了细粒度的权限控制：

- 软件可以决定暴露哪些能力（比如只暴露"读取"，不暴露"删除"）
- 用户可以决定授权哪些能力给 AI（比如只允许"读取笔记"，不允许"修改笔记"）
- 所有操作都有明确的记录（API 调用日志）
- 危险操作可以要求用户确认（MCP 可以集成确认机制）

这就像把"万能钥匙"换成了"门禁卡"——你可以精确控制 AI 能进哪些门、能做哪些事。

**解决体验问题：从"幽灵操作"到"可控交互"**

通过 MCP，AI 和软件的交互是"结构化"的：

- AI 调用什么工具、传入什么参数，都是明确的
- 用户可以看到 AI 要做什么，可以确认或拒绝
- 出错了可以方便地调试（看 API 调用日志）
- 可以并行调用多个工具
- 可以方便地复用和自动化（保存为工作流）

## 四、Notion 与魔搭是如何构建 MCP 的

理解了 MCP 的概念和价值，接下来看看具体的平台是如何构建自己的 MCP 的。

### Notion 的 MCP 构建

Notion 是一个非常受欢迎的笔记和协作工具，它有丰富的 API 生态。构建 MCP 对 Notion 来说是一个自然的延伸。

**Notion MCP 的架构：**

```text
AI 助手 (MCP Client)
    ↓ (MCP 协议)
Notion MCP Server
    ↓ (Notion API)
Notion 后端服务
    ↓
Notion 数据库 / 页面
```

**Notion MCP Server 可能暴露的能力：**

| 工具名称 | 功能 | 权限级别 |
| :--- | :--- | :--- |
| `search_pages` | 搜索页面 | 读取 |
| `get_page_content` | 获取页面内容 | 读取 |
| `get_database` | 获取数据库结构和数据 | 读取 |
| `create_page` | 创建新页面 | 写入 |
| `update_page` | 更新页面内容 | 写入 |
| `append_block` | 在页面末尾追加内容块 | 写入 |
| `create_database` | 创建数据库 | 写入 |
| `add_database_item` | 向数据库添加条目 | 写入 |
| `delete_page` | 删除页面 | 危险（需确认） |

**Notion 构建 MCP 的关键步骤：**

1. **基于现有 API 封装**：Notion 已经有完善的 REST API，MCP Server 本质上是在 API 之上加了一层 MCP 协议的封装。
2. **定义工具和资源**：将 API 端点映射为 MCP 的 Tools 和 Resources，设计合理的参数和返回值。
3. **集成认证机制**：Notion 的 API 使用 OAuth 或 Integration Token 认证，MCP Server 需要集成这些认证机制，确保安全。
4. **实现权限控制**：用户可以配置 MCP Server 的权限（只读/读写/特定页面访问）。
5. **提供提示词模板**：为常见的使用场景（如"整理会议笔记"、"生成周报"）提供预定义的提示词模板。
6. **测试和优化**：确保 MCP Server 的稳定性、性能、错误处理。

**Notion MCP 的价值：**

- 用户可以用自然语言让 AI 操作 Notion（"帮我整理今天的会议笔记"、"把这篇文章总结后存到我的读书笔记数据库"）。
- AI 可以访问 Notion 中的内容作为上下文（"根据我上周的笔记，帮我准备这周的汇报"）。
- 可以构建复杂的自动化工作流（"每天早上自动汇总我的任务并生成日报"）。

### 魔搭（ModelScope）的 MCP 构建

魔搭（ModelScope）是阿里推出的 AI 模型社区和平台，提供模型下载、推理、微调等能力。对于魔搭来说，MCP 的构建有不同的侧重点。

**魔搭 MCP 的架构：**

```text
AI 助手 (MCP Client)
    ↓ (MCP 协议)
ModelScope MCP Server
    ↓ (ModelScope API / SDK)
ModelScope 平台服务
    ├── 模型仓库（下载、搜索）
    ├── 推理服务（在线推理、API 调用）
    ├── 微调服务（微调任务管理）
    └── 数据集（数据集访问、处理）
```

**魔搭 MCP Server 可能暴露的能力：**

| 工具名称 | 功能 | 说明 |
| :--- | :--- | :--- |
| `search_models` | 搜索模型 | 根据关键词、任务类型、框架等搜索模型 |
| `get_model_info` | 获取模型详情 | 模型描述、性能指标、使用方法 |
| `list_datasets` | 列出数据集 | 浏览可用的数据集 |
| `run_inference` | 运行推理 | 调用模型进行推理（文本生成、图像生成等） |
| `create_finetune_task` | 创建微调任务 | 提交模型微调任务 |
| `get_task_status` | 获取任务状态 | 查询微调/推理任务的进度 |
| `download_model` | 下载模型 | 下载模型到本地 |
| `compare_models` | 对比模型 | 对比多个模型的性能和特点 |

**魔搭构建 MCP 的关键特点：**

1. **聚焦 AI 能力**：与 Notion 不同，魔搭的 MCP 不是操作"文档"，而是操作"AI 能力"——模型、数据集、推理、微调。
2. **链式调用的潜力**：魔搭的 MCP 可以让 AI 助手调用其他 AI 模型，形成"AI 编排 AI"的能力（比如"用 A 模型生成文本，再用 B 模型生成配图"）。
3. **资源密集型操作**：模型推理和微调是计算密集型操作，MCP Server 需要处理异步任务、状态查询、结果获取等复杂流程。
4. **与平台深度集成**：魔搭的 MCP 需要与平台的账号体系、计费系统、资源管理深度集成。

**魔搭 MCP 的价值：**

- 用户可以用自然语言搜索和使用 AI 模型（"帮我找一个适合中文文本生成的模型"、"用这个模型帮我写一首诗"）。
- AI 助手可以自动选择和调用合适的模型（"用户需要生成图片，我调用图像生成模型"）。
- 可以构建复杂的 AI 工作流（"先用模型 A 做文本摘要，再用模型 B 做翻译，最后用模型 C 生成配图"）。
- 降低了 AI 模型的使用门槛——用户不需要懂技术细节，只需要用自然语言描述需求。

### 两者的对比与启示

| 维度 | Notion MCP | 魔搭 MCP |
| :--- | :--- | :--- |
| **核心能力** | 文档/笔记的读写和管理 | AI 模型的搜索、推理、微调 |
| **操作对象** | 页面、数据库、内容块 | 模型、数据集、推理任务 |
| **交互模式** | 主要是同步的 CRUD 操作 | 包含大量异步任务（推理、微调） |
| **用户价值** | 让 AI 帮你管理和处理笔记 | 让 AI 帮你使用和编排 AI 模型 |
| **构建难度** | 中等（基于现有 API 封装） | 较高（需要处理异步任务、资源管理） |

**两者的共同启示：**

1. MCP 的核心是"将软件能力标准化暴露给 AI"。
2. 构建 MCP 需要基于现有的 API/SDK，而不是从零开始。
3. 安全和权限控制是必须的。
4. 好的 MCP 不仅暴露工具，还提供提示词模板和使用场景指导。
5. MCP 的价值在于"降低 AI 使用软件能力的门槛"。

## 五、未来展望

### MCP 会成为 AI 时代的"USB 接口"

就像 USB 接口统一了各种外设的连接方式，MCP 有望成为 AI 时代统一各种软件/服务连接方式的标准协议。

未来，可能每个软件都会有自己的 MCP Server，就像现在每个网站都有 API 一样。AI 助手可以连接到成百上千个 MCP Server，调用各种软件的能力，为用户提供无缝的体验。

### "AI 直接操纵软件"不会完全消失，但会成为补充

虽然 MCP 是更优的解决方案，但"AI 直接操纵软件"（通过屏幕理解和模拟操作）不会完全消失。它会在以下场景中作为补充：

- 没有 API 的老旧软件
- 没有 MCP 支持的小众软件
- 需要模拟人类操作的测试场景
- 临时的、一次性的操作

但对于主流软件，MCP 会成为主要的连接方式。

### 安全和治理会越来越重要

随着 AI 通过 MCP 连接的软件越来越多，安全和治理问题会越来越突出：

- 如何防止 AI 被诱导执行危险操作？
- 如何保护用户的数据隐私？
- 如何审计 AI 的操作？
- 如何在 AI 出错时快速止损？

这些问题需要 MCP 协议、平台、AI 模型共同解决。

### "AI 编排 AI"会成为新的范式

魔搭 MCP 展示了一个有趣的方向：**AI 助手通过 MCP 调用其他 AI 模型，形成"AI 编排 AI"的能力。**

未来，AI 助手可能会：

- 自动判断用户需求需要哪些 AI 能力
- 自动选择和调用合适的模型
- 将多个模型的能力组合起来，完成复杂任务
- 自动优化和调整模型参数

这会大大降低 AI 的使用门槛，让每个人都能轻松使用最先进的 AI 能力。

## 六、总结

回到最初的问题：**为什么 AI 不能直接操纵软件？**

答案是：**技术上不可靠、安全上太危险、体验上太差。**

- **技术上**：软件的界面是为人类设计的，AI 通过"看界面、点按钮"的方式操纵软件，不准确、不可靠、效率低。
- **安全上**：让 AI 直接操纵软件，等于给了它"万能钥匙"，一旦出错或被攻击，后果严重。
- **体验上**："幽灵操作"让用户无法预测和控制，出错了难以调试和恢复。

**MCP（Model Context Protocol）就是为了解决这些问题而生的。** 它在 AI 和软件之间提供了一个标准化的、安全的、高效的"协议层"：

- AI 不需要操纵界面，而是直接调用软件暴露的 API（通过 MCP 封装）
- 权限可控、操作可审计、危险操作可确认
- 交互结构化、用户可控制、可并行可复用

Notion 和魔搭的 MCP 构建实践展示了两种不同的路径：

- **Notion**：将文档/笔记的读写管理能力标准化暴露给 AI
- **魔搭**：将 AI 模型的搜索、推理、微调能力标准化暴露给 AI

两者的共同启示是：**MCP 的核心价值是"降低 AI 使用软件能力的门槛"，让用户可以用自然语言轻松调用各种软件的能力。**

未来，MCP 有望成为 AI 时代的"USB 接口"，连接起成千上万的软件和服务，让 AI 真正成为每个人的"全能助手"。

> **一句话总结**：AI 不能直接操纵软件，是因为技术不可靠、安全太危险、体验太差。MCP 通过"标准化 API 层"解决了这些问题，是 AI 与软件连接的正确方式。Notion 和魔搭的实践展示了 MCP 的两种典型路径——文档管理和 AI 能力编排。
