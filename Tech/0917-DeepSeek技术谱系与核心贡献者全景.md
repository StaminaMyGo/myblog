# DeepSeek 技术谱系与核心贡献者全景

DeepSeek 是近年开源大模型浪潮中最具代表性的样本：它以量化交易公司为母体、以 140 人以内的高密度团队支撑起从 67B 到 671B 的完整模型谱系，用 MLA、DeepSeekMoE、纯强化学习三条关键路线改写了"推理成本—训练效率—推理能力"之间的传统权衡。本文按时间线梳理其技术演进，并逐一还原每个关键节点的核心贡献者。

## 一、创始背景：从量化交易到通用人工智能

DeepSeek 的起点不在 AI 实验室，而在量化交易。创始人梁文锋 2008 年起探索全自动量化交易，2015 年创立幻方量化，2016 年推出首个深度学习交易模型。2020 年和 2021 年，幻方先后建成"萤火一号"和"萤火二号"AI 训练平台，为后续大模型研发积累了算力基础。

2023 年 5 月，梁文锋宣布进军通用人工智能；同年 7 月，幻方量化孵化出杭州深度求索人工智能基础技术研究有限公司，DeepSeek 正式成立。公司完全由幻方量化资助，团队规模始终控制在 140 人以内，成员几乎全部来自清华、北大、中山大学、北邮等国内高校，不少还是在读博士。

::: tip 组织基因
幻方量化留下的两大遗产：一是自建算力平台（萤火系列）的工程能力，二是"小团队 + 高密度 + 长周期投入"的组织范式。这两点直接决定了 DeepSeek 后续"用工程效率换成本、用方法论创新换能力"的技术路线。
:::

## 二、技术谱系总览：五代模型的一条主线

| 模型 | 发布时间 | 参数量 | 关键创新 | 里程碑意义 | 核心贡献者 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DeepSeek LLM 67B** | 2023-11 | 7B / 67B | 系统验证 Scaling Laws，2T token 混合语料 | 确立开源定位 | 王炳宣 |
| **DeepSeek-V2** | 2024-05 | 236B（激活 21B） | **MLA + DeepSeekMoE** | 解决推理效率与训练成本矛盾 | 高华佐、曾旺丁、陈德里、罗福莉 |
| **DeepSeek-V3** | 2024-12 | 671B（激活 37B） | FP8 混合精度、DualPipe、无辅助损失负载均衡 | 工程效率巅峰 | 梁文锋、陈德里 |
| **DeepSeek-R1** | 2025-01 | 671B 基座 + 蒸馏系列 | **纯强化学习激励推理** | 开辟推理能力新路径 | Junxiao Song、邵智宏、朱琪豪、潘梓正等 |
| **DeepSeek-V4** | 2026-04 | 未披露（含 mHC 架构） | 近 300 人署名、大规模工程化 | 转向阶段，人才外流显现 | 梁文锋领衔集体署名 |

从初代到 V4，技术路线有一条清晰主线：**初代验证 Scaling Law 并确立开源定位 → V2 用 MLA 与 MoE 解决推理效率与训练成本的矛盾 → V3 将效率推向极致并公开 FP8 工程栈 → R1 用纯强化学习开辟推理能力新路径 → V4 进入更大规模工程化阶段，同时面临核心人才向外流动的现实。**

## 三、初代模型（2023 年 11 月—2024 年 1 月）：DeepSeek LLM 67B

DeepSeek 的首个模型于 2023 年 11 月发布，技术报告《DeepSeek LLM: Scaling Open-Source Language Models with Longtermism》于 2024 年 1 月 5 日公开。模型包含 7B 和 67B 两个版本，团队系统研究了 Scaling Laws，给出实证拟合公式，并基于 2T token 的中英文与代码混合语料完成训练。67B 在代码、数学和推理领域超越了 LLaMA-2 70B。

**核心作者**：王炳宣是 DeepSeek 第一代大语言模型的核心作者，并参与了此后历代模型的一系列重要研发工作。王炳宣后离开 DeepSeek 加入腾讯。

## 四、V2（2024 年 5 月）：MLA 架构与 MoE 路线的确立

DeepSeek-V2 是技术谱系中的关键转折点。模型总参数 236B，每 token 激活 21B，支持 128K 上下文。相比 DeepSeek 67B，V2 性能显著更强，同时节省 42.5% 训练成本，KV 缓存减少 93.3%，最大生成吞吐提升至 5.76 倍。

V2 的两项核心架构创新是 **MLA** 和 **DeepSeekMoE**：

- **MLA（Multi-head Latent Attention）**：通过低秩键值联合压缩，在保持优于 MHA 性能的同时大幅降低推理时的 KV 缓存占用。
- **DeepSeekMoE**：通过稀疏计算实现经济高效的训练，为后续更大规模模型奠定基础。

**MLA 架构的核心贡献者**：高华佐和曾旺丁为 MLA 架构做出了关键创新。高华佐是北大物理系毕业，曾旺丁是北邮研究生，师从张洪刚教授。此外，赵成钢作为训练/推理基础架构工程师参与其中，他曾是超算团队成员，三次获得世界大学生超算竞赛冠军。

**MoE 架构的核心贡献者**：陈德里，北大毕业，在 NLP 和图神经网络领域积累了一万多引用。2023 年加入 DeepSeek 后，他的名字出现在 DeepSeekMoE、DeepSeek-V2、DeepSeek-V3、DeepSeek-V4、DeepSeek-R1、DeepSeek-Coder 每一个重要论文的作者栏中。MoE 架构的专家专业化设计，陈德里是核心贡献者。

**V2 其他核心成员**：罗福莉，被称为"AI 天才少女"，2022 年加入幻方量化从事深度学习工作，后担任 DeepSeek 深度学习研究员，参与研发 DeepSeek-V2 等模型，后离开加入小米。

::: note 为什么 MLA 是"底座级"创新
KV 缓存占用直接决定推理吞吐与长上下文成本。MLA 通过低秩压缩把每 token 的 KV 缓存压到远低于 MHA 的水平，这不仅是 V2 的胜负手，更成为 V3、R1 全系列沿用的事实标准——高华佐与曾旺丁的名字因此贯穿整个 V 系列。
:::

## 五、V3（2024 年 12 月）：工程效率的巅峰

DeepSeek-V3 总参数 671B，每 token 激活 37B，在 14.8 万亿 token 上预训练。V3 延续了 V2 验证过的 MLA 和 DeepSeekMoE 架构，同时引入两项关键创新：**无辅助损失的负载均衡策略**和**多 token 预测训练目标**。整个训练仅需 2.788M H800 GPU 小时，且全程未出现不可恢复的 loss 尖峰或回滚。

V3 真正的突破在于**基础设施栈**：FP8 混合精度训练在大规模上首次成功落地并公开配方、DualPipe 流水线并行、手工调优的 all-to-all 内核，以及无辅助损失的 MoE 负载均衡方案。

**核心作者**：论文以 DeepSeek-AI 团队集体署名，梁文锋作为 CEO 是署名作者之一。陈德里再次作为核心贡献者出现在作者名单中。

| V3 基础设施创新 | 解决的问题 |
| :--- | :--- |
| FP8 混合精度训练 | 在 671B 规模上降低显存与带宽需求，首次大规模公开落地配方 |
| DualPipe 流水线并行 | 减少流水线气泡，提升 GPU 利用率 |
| 手工调优 all-to-all 内核 | 优化 MoE 跨节点通信瓶颈 |
| 无辅助损失负载均衡 | 避免传统辅助损失对模型质量的干扰，同时保证专家利用率 |

## 六、R1（2025 年 1 月）：纯强化学习激励推理

DeepSeek-R1 的核心贡献在于证明了**不依赖人类标注推理轨迹，仅通过纯强化学习即可激励大模型的推理能力**。团队在 V3-Base 上构建 R1-Zero，采用基于规则的奖励和 GRPO，使模型自发涌现出长链式思考、自反思、验证和动态策略适应等高级推理模式。随后通过多阶段冷启动、拒绝采样、监督微调和混合 RL 训练得到最终 R1。

R1 在数学、代码、STEM 等可验证任务上接近甚至超过 OpenAI o1-1217，蒸馏后 1.5B 小模型已超越 GPT-4o 等基线。该工作于 2025 年 9 月登上《自然》封面，**梁文锋为通讯作者**。

**GRPO 算法的提出者**：Junxiao Song，浙江大学自动化本科，2015 年获香港科技大学电子与计算机工程博士学位，导师 Daniel Palomar 评价他"非常注重数学"，在实验室被称为"大师"。他加入 DeepSeek 后提出了 GRPO 算法，该算法已应用于 DeepSeek-R1 在内的多款模型训练，他还在高效训练和模型蒸馏工作中扮演重要角色。

**R1 核心作者名单**：Daya Guo、Dejian Yang、Haowei Zhang、Junxiao Song、Peiyi Wang、Qihao Zhu、Zhihong Shao 等。潘梓正也是 R1 的核心贡献者之一，他曾在英伟达实习并获得转正 offer，但选择加入当时还名不见经传的 DeepSeek。邵智宏，清华交互式人工智能课题组博士生，师从黄民烈教授，是 R1 的核心作者之一。朱琪豪，北大计算机学院 2024 届博士，研究方向为深度代码学习，同样在核心作者之列。

```text
R1-Zero 训练路径（纯 RL 验证阶段）
V3-Base
  └─ 基于规则的奖励 + GRPO 强化学习
       └─ R1-Zero：涌现长链思考 / 自反思 / 验证 / 动态策略适应
       （证明：无需人类标注推理轨迹，RL 即可激励推理能力）

R1 完整训练路径（多阶段）
V3-Base
  └─ 冷启动（少量高质量数据）
       └─ 拒绝采样 → 监督微调（SFT）
            └─ 混合 RL 训练
                 └─ R1（数学/代码/STEM 接近或超过 o1-1217）
```

## 七、V4（2026 年 4 月）：近 300 人署名的转向

DeepSeek-V4 技术报告长达 58 页，作者名单近 300 人，**创始人梁文锋与所有研究员、工程师并列署名**。名单中 10 人标注"已离职"，包括王炳宣、魏浩然、郭达雅等核心骨干，流向腾讯、字节跳动等大厂，几乎覆盖了基座模型、推理、OCR、多模态四条核心技术线。V4 报告还透露了 mHC 架构等信息。

值得注意的是，**陈德里在 V4 之后主导了战略转向**——从"养马"（开源模型）转向"造车"（构建 Code Harness），组建团队对标 Claude Code。

::: warning 组织信号
V4 的"近 300 人署名"与"10 人标注离职"并存，是一个值得关注的结构性信号：团队规模扩大与核心人才外流同时发生，说明 DeepSeek 正从"少数人定义架构"走向"更大规模的工程组织"，而骨干流失覆盖四条核心技术线，将直接影响下一阶段的技术连续性。
:::

## 九、演进逻辑与组织特征

**技术主线的五步跳**：

1. **初代**：验证 Scaling Law 与开源定位，证明"小团队也能训大模型"。
2. **V2**：用 MLA + MoE 同时解决推理效率与训练成本，确立架构底座。
3. **V3**：把工程效率推向极致，FP8、DualPipe 等基础设施创新公开化。
4. **R1**：用纯强化学习打开推理能力新路径，方法论层面改写行业共识。
5. **V4**：进入更大规模工程化，同时暴露人才流动与战略转向。

**组织特征**：DeepSeek 始终维持小规模高密度，核心贡献者高度集中在少数人身上——陈德里横跨 MoE 到 R1 几乎全部关键项目，Junxiao Song 以 GRPO 算法奠定 R1 的方法论基础，高华佐和曾旺丁在 MLA 上的创新为整个 V 系列架构提供了底座。这种**"少数人定义架构，集体完成工程"**的模式，是 DeepSeek 技术谱系最显著的组织特征，也是其在人才外流压力下仍能保持技术连续性的原因所在。

## 专业名词释义

| 名词 | 英文 | 核心概念 | 来源/背景 | 解决什么问题 |
| :--- | :--- | :--- | :--- | :--- |
| Scaling Laws | 规模定律 | 模型性能随参数量、数据量、算力按幂律增长的实证规律 | Kaplan 等（2020），DeepSeek 初代给出拟合公式 | 指导算力与数据配置 |
| token | Token | 文本切分后的最小处理单元（词/子词/字符） | 自然语言处理 | 定义模型输入输出粒度 |
| 混合语料 | Mixed Corpus | 多语言与多领域（中英+代码）数据组合 | 预训练实践 | 提升多语言与代码能力 |
| KV 缓存 | Key-Value Cache | 推理时为避免重复计算而缓存的历史注意力键值 | Transformer 推理优化 | 降低推理延迟与显存占用 |
| MLA | Multi-head Latent Attention | 低秩键值联合压缩的注意力机制，DeepSeek 自研 | DeepSeek-V2 | 大幅压缩 KV 缓存，降本增效 |
| MHA | Multi-Head Attention | 标准多头注意力，Transformer 基础机制 | Vaswani 等（2017） | 作为 MLA 的性能对标基线 |
| 低秩压缩 | Low-Rank Compression | 用低维隐向量近似高维矩阵，减少存储与计算 | 矩阵分解理论 | 在保持性能前提下压缩缓存 |
| MoE | Mixture of Experts | 稀疏专家混合架构，每 token 仅激活部分专家 | Shazeer 等（2017） | 参数扩容而不等比增加计算 |
| DeepSeekMoE | — | DeepSeek 版 MoE，强调专家专业化与负载均衡 | DeepSeek-V2 | 经济高效地训练超大模型 |
| FP8 混合精度 | FP8 Mixed Precision | 以 8 位浮点为主体的混合精度训练方案 | 英伟达/DeepSeek-V3 | 降低显存带宽需求、加速训练 |
| DualPipe | — | 双向流水线并行算法，减少流水线气泡 | DeepSeek-V3 | 提升大规模训练 GPU 利用率 |
| all-to-all | All-to-all Communication | MoE 跨节点专家通信的集合通信模式 | 分布式训练 | 优化专家并行通信瓶颈 |
| 负载均衡 | Load Balancing | 使各专家/设备负载均匀的策略 | MoE 工程 | 避免部分专家过载闲置 |
| 多 token 预测 | Multi-Token Prediction | 一次预测多个未来 token 的训练目标 | DeepSeek-V3 等 | 提升训练效率与样本利用 |
| 强化学习 | Reinforcement Learning (RL) | 智能体通过与环境交互、以奖励信号驱动策略优化的学习范式 | 机器学习 | 让模型自主探索推理策略 |
| GRPO | Group Relative Policy Optimization | 组内相对策略优化，以组内奖励相对比较替代价值网络 | Junxiao Song 提出，DeepSeek-R1 | 简化 RL 训练、降低算力开销 |
| 基于规则的奖励 | Rule-based Reward | 以可验证结果（如答案正确性）而非奖励模型评分的奖励机制 | DeepSeek-R1 | 规避奖励黑客，稳定训练 |
| R1-Zero | — | 无监督微调直接 RL 的中间版本，验证纯 RL 可行性 | DeepSeek-R1 | 证明推理能力可自发涌现 |
| 冷启动 | Cold Start | 用少量高质量数据引导模型进入有效学习区间 | DeepSeek-R1 | 提升 RL 训练稳定性与可读性 |
| 拒绝采样 | Rejection Sampling | 仅保留高分输出作为训练数据的采样策略 | 对齐研究 | 筛选高质量监督数据 |
| 监督微调 | Supervised Fine-Tuning (SFT) | 用标注数据对模型进行有监督训练 | 迁移学习 | 对齐指令与输出格式 |
| 蒸馏 | Distillation | 用大模型输出训练小模型，迁移能力 | Hinton 等（2015） | 以低成本获得高性能小模型 |
| 长链式思考 | Long Chain-of-Thought | 模型生成的、包含多步推理与自反思的长程思维过程 | R1 涌现现象 | 提升复杂推理任务表现 |
| mHC | — | DeepSeek-V4 报告披露的新架构信息 | DeepSeek-V4 | 待后续公开资料进一步确认 |
| Code Harness | 代码工具链 | 面向 Agent 编程的代码执行与工具调用环境 | 战略转向方向 | 对标 Claude Code 类产品 |
